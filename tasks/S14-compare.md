# Задача S14 — Порівняння товарів side-by-side

**Роль:** Виконавець · **Автор:** Диригент, 2026-07-25 · **Статус:** `E1 в роботі`
**Залежності:** матчинг (offers_n), discount_event (бейджі), S12 (характеристики).

### 0. Навіщо
Остання продуктова фіча зі списків: обрати 2-3 товари → екран порівняння колонками
(ціни, бейджі, характеристики). Все з наявних даних, без нового збору.

### 1. Межі
**In:** до 4 товарів; для кожного — назва/фото/ціна/бейдж/offers_n; таблиця
характеристик (union атрибутів з S12, вирівняна по колонках, відсутнє = «—»).
**Out:** «розумний» матчинг схожих (юзер сам обирає); графіки; специфікації-фасети.

### 2. Сервер
`GET /api/compare?ids=1,2,3` → `{products:[{store_product_id,title,image_url,
price_kop,badge_state,declared_pct,offers_n}], spec_rows:[{name, values:[по колонках]}]}`.
Характеристики — з product_specs (S12); покриття неповне → чесно null. Порядок
колонок = порядок ids. Ліміт 4 (UI).

### 3. MAUI
- Режим вибору: тап-toggle «порівняти» на картках стрічки (макс 4); плаваюча кнопка
  «Порівняти (N)».
- ComparePage: горизонтальні колонки товарів (фото/назва/ціна/бейдж) + таблиця
  характеристик під ними (рядок-атрибут × колонки-товари).

### 4. DoD
- [ ] qdb.compare_products (базові + union характеристик); ендпойнт; тест round-trip.
- [ ] MAUI: режим вибору + ComparePage + VM; збірка 0 errors; прогін емулятор.

### 5. Guardrails
- Лише факти (ціна/бейдж/характеристики з провенансом) — жодних оцінок.
- Характеристики частково покриті (S12 у вільних слотах) → «—», не вигадувати.
